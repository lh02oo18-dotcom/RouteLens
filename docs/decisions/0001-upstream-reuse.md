# ADR-0001：复用 Crowd Counter 并分层扩展 RouteLens

- 状态：已采纳
- 日期：2026-10-11
- 上游基线：`Youssef-Azzam/Crowd_Counter@126f5c5`

## 背景

项目需要同时覆盖计算机视觉、数据挖掘、开源复用和工程迭代。完全重写检测与跟踪会消耗大量时间，却不能突出轨迹模式和异常解释这一核心问题。

## 决策

保留上游的检测器、跟踪器、视频主循环、基础统计、导出和界面入口。RouteLens 在稳定的轨迹记录之上增加独立的特征、模式挖掘、异常事件和证据卡模块。新增算法优先写成不依赖 UI 的纯计算组件，通过数据结构接入主流水线。

## 接口复用边界

| 层 | 复用 | RouteLens 改造 |
|---|---|---|
| 输入与视频循环 | OpenCV 输入、帧处理回调 | 后续增加演示数据选择与进度反馈 |
| 检测 | Ultralytics YOLO 人员检测 | 不重新训练时保持适配器接口 |
| 跟踪 | ByteTrack、BoT-SORT、CSRT | 增加轨迹质量指标，不修改后端内部算法 |
| 基础分析 | 越线、占用、停留、轨迹点 | 新增统一轨迹对象与事件协议 |
| 数据挖掘 | 无 | 轨迹特征、DBSCAN、偏离评分 |
| 可解释输出 | 基础 CSV/JSON/标注视频 | 异常原因、指标、阈值和关键帧证据卡 |

## 备选方案

- 从零开发：复用证据弱、风险高，拒绝。
- 只改界面和阈值：创新不足，拒绝。
- 直接采用大型完整监控平台：本机部署和理解成本过高，拒绝。

## 后果

优点是主路径可先运行、迭代边界清楚、适合现场演示。代价是必须清楚保留上游署名，并通过 Git 历史、CHANGELOG 和文档准确区分复用与新增内容。
