# 渐进式实施记录

## 2026-10-11：开源基线接入

### 本轮目标

选择与方案接近的开源底座，在目标电脑上跑通检测、跟踪、导出和 Web 界面，并建立后续创新的清晰边界。

### 完成内容

- 选择 `Youssef-Azzam/Crowd_Counter@126f5c5` 作为底座。
- 创建 `feature/routelens-baseline` 分支。
- 建立 Python 3.12 虚拟环境并安装 CUDA 版 PyTorch。
- 验证 RTX 4060、YOLO11n、ByteTrack、CSV/JSON/MP4 导出和 Streamlit。
- 把自动发现的 `lap` 运行依赖显式写入 requirements。
- 将 Ultralytics 和 Pytest 的运行目录移到项目内 `.runtime`，规避 Windows 用户目录权限问题。
- 建立 RouteLens README、复用决策、路线图、评分矩阵和 GitHub 协作配置。
- 创建公开仓库，并按配置、核心流水线、跟踪器、文档、测试和工具拆分提交。
- 创建功能 Issue #1 与基线 Pull Request #2，由 GitHub Actions 验证 Python 3.10/3.12。

### 遇到的问题与解决

1. Git HTTPS 后端无法加载：改用系统 Git 并指定 OpenSSL 后端完成克隆。
2. Ultralytics 尝试写入用户配置目录：通过 `YOLO_CONFIG_DIR` 使用项目本地运行目录。
3. ByteTrack 首次运行自动安装 `lap`：将其加入 requirements，避免其他机器首次运行产生隐式变更。
4. Pytest 偶发无法访问 AppData 临时目录：在 `pyproject.toml` 中固定项目本地临时目录和缓存。

### 验证结果

- 8 项单元测试通过。
- Ruff 通过。
- `pip check` 无依赖冲突。
- Streamlit 健康端点返回 HTTP 200。
- 30 帧 GPU 冒烟测试识别 4 个轨迹 ID，并生成完整输出。

### 当前阶段

- 公开仓库、Issue、Pull Request 和 Actions 记录已经建立。
- PR #2 已在 4 项 GitHub Actions 检查全部通过后合并，`v0.1.0` 已发布为 Latest Release。
- RouteLens 轨迹特征、异常检测和证据卡已记录在 Issue #1，属于后续迭代。

## 2026-10-15：迭代 1 —— 轨迹特征与可解释规则

### 本轮目标

将上游检测/跟踪产生的原始轨迹转换为 RouteLens 自有的可解释特征和异常事件，同时保持原有主路径稳定。

### 完成内容

- 新增独立纯计算模块 `trajectory_analysis.py`。
- 输出速度、方向、路径长度、净位移比、转向角、活动半径和数据质量计数。
- 逆行规则要求方向冲突同时满足持续时间和距离，徘徊规则联合时长、半径和路径长度。
- 新增 CSV/JSON 导出、Streamlit 参数控件和异常列表。
- 新增合成轨迹示例和边界情况测试，不使用合成数据声称真实精度。

### 风险处理

- 不改动 YOLO 权重和跟踪器接口，降低对基线的回归风险。
- 重复时间戳不参与速度除法，缺帧显式记录为质量特征。
- 逆行默认关闭，只有设定场景期望方向后才判定。
- 文档明确像素单位、ID 切换和场景阈值限制。

### 验证结果

- Ruff 通过。
- 14 项单元测试通过。
- `pip check` 无依赖冲突。
- Streamlit 健康端点和合成轨迹演示完成后再合并。

## 2026-10-18：迭代 2 —— 主路线挖掘与偏离评分

### 本轮目标

在不修改检测器和跟踪器的前提下，从多条轨迹中发现重复通行模式，并将异常判断从单纯手写规则扩展为数据驱动的路线偏离评分。

### 完成内容

- 按累计行进距离将不同长度轨迹重采样为固定点数，并使用同一场景边界归一化。
- 使用无新增依赖、结果确定的 DBSCAN 实现聚类，输出主路线原型和噪声轨迹。
- 计算轨迹到最近路线原型的均方根距离，并输出指标、阈值和证据引用。
- 将路线分配、路线原型、摘要和偏离事件接入 Streamlit、主流水线及 CSV/JSON 导出。
- 新增事件级精确率、召回率、F1 评价工具和合成参数扫描脚本。

### 风险处理

- 若没有形成满足最小样本数的路线簇，不把 DBSCAN 噪声直接判为异常。
- 短轨迹和静止轨迹不参与聚类，并在摘要中记录数量。
- 不增加 scikit-learn 等大型依赖，降低 Windows 安装和 CI 风险。
- 合成结果明确标记为流程验证，不冒充真实视频准确率。

### 验证结果

- Ruff 通过。
- 21 项单元测试通过。
- 合成参数扫描成功导出 12 组阈值组合及 TP、FP、FN、Precision、Recall、F1。
- 30 帧短视频端到端冒烟测试识别 4 条有效轨迹并生成全部新增导出；因未形成 3 条相似路线，安全返回 `insufficient_cluster_support` 和 0 个偏离事件。
- 真实小型标注集仍待建立，因此本版本不报告真实世界准确率。

## 2026-10-22：迭代 3 —— 异常证据卡与稳定交付

### 本轮目标

让异常结果不仅“有分数”，还能够回到关键帧、目标轨迹、触发指标和阈值，并为课堂演示提供不依赖临场网络的回退路径。

### 完成内容

- 新增独立 `evidence.py` 模块，为逆行、徘徊和路线偏离事件生成 1280×720 证据卡。
- 本地视频读取事件中间帧，叠加轨迹和目标框；无法回读的摄像头或网络流明确使用 `generated_canvas`。
- 将证据卡索引、帧来源、指标、阈值和轨迹引用导出为 CSV/JSON，并在 Streamlit 中展示。
- 新增确定性合成证据卡演示、GitHub Pages 静态项目页和发布工作流。
- 同步 README、架构、路线图、演示讲稿、已知问题和 Changelog。

### 风险处理

- 不缓存或提交真实监控视频，证据卡仅在用户指定输出目录生成。
- 隐私模糊开启时沿用到证据关键帧。
- 无法读取原始关键帧时显式记录回退状态，不伪造画面来源。
- 合成演示继续标记为流程验证，不写成真实准确率。
- 真实标注、独立测试集和事件级真实指标仍作为数据缺口保留。

### 本机验证

- `pytest -q`：24 项测试通过。
- `ruff check` 与 `pip check`：通过。
- 30 帧本地视频端到端冒烟测试正常完成，导出证据卡清单；该样例未触发异常，因此证据卡数量为 0，状态为 `no_anomaly_events`。
- Streamlit 健康检查返回 HTTP 200；Pages 工作流配置通过 YAML 解析。
- 使用本地视频关键帧完成证据卡读取与渲染集成检查；注入事件仅用于验证渲染链路，不作为算法检测结果或准确率证据。
