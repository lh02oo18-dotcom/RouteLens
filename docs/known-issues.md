# 已知问题

## 当前限制

- 首次运行需要联网下载 YOLO 权重；断网演示前应提前完成下载。
- CUDA 版 PyTorch 需要按显卡驱动匹配安装，普通 `requirements.txt` 不固定 CUDA wheel。
- 密集遮挡可能导致轨迹 ID 切换，继而影响停留和路线分析。
- 默认越线坐标不一定适合用户视频，需要按画面调整。
- 当前 Streamlit 处理长视频时会阻塞页面，尚无任务队列或取消按钮。
- 逆行与徘徊为可解释阈值规则，暂未完成真实数据误报/漏报评估。
- 路线聚类依赖同一场景中足够数量的完整轨迹；样本不足时系统返回 `insufficient_cluster_support`，不会输出偏离事件。
- 当前 DBSCAN 使用 O(n²) 距离矩阵，面向小型离线数据，不适合未经分批的超大轨迹库。
- 速度和距离使用像素单位，未做透视标定时不能解释为真实世界速度。
- 本地视频可以回读异常关键帧；摄像头和网络流在会话结束后可能无法回读，因此证据卡会明确使用 `generated_canvas` 回退。

## 已解决的环境问题

- 旧版 `.runtime/pytest` 与用户临时目录可能残留异常 ACL；v1.0.0 将测试临时文件写入忽略的 `outputs/pytest-v1` 并关闭非必要缓存。
- Ultralytics 默认写入用户配置目录；运行配置已重定向到项目内忽略的 `.runtime`。

## 数据与评估缺口

- 现有冒烟视频由静态图片生成，只验证执行链路。
- 尚未建立真实异常事件的人工标注集。
- 尚未报告真实视频上的精确率、召回率、误报率或阈值敏感性。
- 已提供事件级评价和合成参数扫描，但合成指标不能代替真实视频指标。

每个问题都应转成 GitHub Issue，并在修复提交和 Pull Request 中引用编号。
